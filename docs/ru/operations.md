# Установка и эксплуатация

[English](../en/operations.md) · [Русский](operations.md) · [Deutsch](../de/operations.md)

## Подготовка Mattermost

В System Console включите Bot Account Creation и Personal Access Tokens.
Создайте личный токен обычного пользователя system_admin: MM_TOKEN. Токен бота
не позволяет создавать других ботов. Создайте отдельного бота-менеджера и сохраните
его токен как MM_BOT_TOKEN. Добавьте менеджера в команды и каналы для упоминаний.
Для личных сообщений настройка канала не нужна.

## Настройка и запуск

Скопируйте `.env.example` в `.env`, ограничьте права файла, задайте MM_URL, MM_TOKEN,
MM_BOT_TOKEN. Не коммитьте секреты. Установите MM_DEFAULT_LANGUAGE=ru (en/ru/de),
MM_DISPLAY_TIMEZONE=UTC либо IANA-зону. Оставьте MM_VERIFY_SSL=true и доверенный CA.
MM_APPROVERS, MM_CATALOG_VIEWERS, MM_FEEDBACK_HANDLERS — имена через запятую,
независимые роли. Пустой список обработчиков отключает обращения. После изменений
перезапустите приложение.

Приоритет БД: DB_URL, полный набор DB_HOST/DB_PORT/DB_NAME/DB_USER/DB_PASSWORD,
затем DB_PATH (SQLite). Обеспечьте постоянное хранилище. Для Compose задайте закреплённый
MM_BOT_MANAGER_IMAGE, выполните `docker compose up -d`, проверьте `docker compose logs`.
Контейнер работает без root с файловой системой только для чтения; сохраняйте эти настройки.
Локально нужны Python 3.14, `uv venv .venv`, `uv sync --frozen --extra postgres`,
затем `uv run --no-sync mm-bot-manager --language ru`.

Для Kubernetes задайте mattermost.defaultLanguage=en/ru/de в overlay площадки;
передайте секреты через существующие Secrets либо External Secrets Operator.
До развёртывания выберите БД, хранилище и kube-context. Подробные команды и параметры:
[инструкция Kubernetes](../kubernetes.md), [справочник Helm](../../deploy/helm/mm-bot-manager/README.md).
Скрипт развёртывания проверяет сохранённые настройки площадки перед установкой.
Эти платформенные справочники сопровождаются на английском.

## Обновление, копии и восстановление

Перед обновлением остановите старый менеджер. Не запускайте два экземпляра с одной БД.
Создайте копию PostgreSQL через pg_dump, проверьте pg_restore --list и восстановление
в изолированную БД. Для SQLite остановите менеджер и используйте backup API или
команду `.backup`; не копируйте активную БД без WAL. Храните копии закрыто.
После восстановления проверьте владельцев, заявки, настройки и обращения.
Для PostgreSQL в Kubernetes используйте scripts/kubernetes-db.sh и проверку из инструкции.
Восстановление перезаписывает новые изменения: сначала проверяйте отдельно.

Миграция 3 расширяет языки, сохраняя язык и формат каталога; выполняется транзакционно
при запуске. Перед откатом приложения остановите его и выполните в той же БД
`UPDATE user_preference SET language = 'auto' WHERE language = 'de';`.
Сохраните расширенное ограничение и запись миграции; схему назад не откатывайте.
Возврат старой копии теряет новые записи. Перед любым изменением создайте копию.

## Диагностика

Проверьте `!version`, журнал запуска и настроенную локальную проверку здоровья.
403 при создании обычно означает неверный тип MM_TOKEN или отключённое создание ботов.
Для ошибок API сохраняйте диагностический ID, не секреты. При неизвестном исходе записи
не повторяйте команду вслепую. Остановите менеджер и изучите
`uv run --no-sync python -m mm_bot_manager.recovery --language ru --help`.
Административная справка работает без серверных секретов. Доступны --language en/de.
Смена языка не меняет права и не переводит пользовательский текст.
